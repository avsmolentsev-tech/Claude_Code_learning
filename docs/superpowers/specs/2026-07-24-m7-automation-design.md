# Дизайн модуля М7 «Автоматизация рутины и документооборота»

Дата: 2026-07-24 · Статус: согласован Александром (сессия 23–24.07.2026)

## Контекст

М0–М6 полностью готовы и опубликованы (22 урока + инструкция, myaipro.ru/kurs). М7 — следующий по порядку. По ранее зафиксированным пожеланиям Александра модуль должен покрыть: расписания/headless/субагенты, n8n vs Claude-агенты, разбор входящих, QA-контроль менеджеров, нейро-сотрудника и флагманский практикум — тендерного агента.

Решения, принятые в этом брейншторме:
- Тендер — **реальный, с zakupki.gov.ru (ЕИС)**, как образец.
- Профиль компании для анализа соответствия — **нейтральный демо-профиль** (по образцу «мебель в Казани»), подбирается под отрасль найденного тендера.
- Разбор входящих — **на реальной почте Александра**; блокер: Gmail-коннектор к Claude пока не подключён (только Google Drive). Паттерн тот же, что с вебхуком Bitrix24 в М6-02: урок пишется, когда Александр сделает разовый шаг подключения.
- QA-контроль — **реалистичный демо-пример** (у Александра своих транскриптов нет; у студентов данные в разных системах — их случай покрыт чек-листом материалов, п. 7).
- n8n — **не отдельный урок**, а сравнение внутри урока 1, на живом n8n-инстансе этого сервера (порт 5678, реально работает).
- «Нейро-сотрудник» — **не отдельный урок**, а связующая рамка/вывод модуля.

## Структура: 4 урока

### Урок 1. Агент по расписанию: работает, пока ты спишь
- Headless-режим (`claude -p "…"`), выход агента из интерактивного диалога в скрипты.
- Cron: реальное расписание на реальном сервере (живая демонстрация, не теория).
- Субагенты: параллельная работа над независимыми задачами.
- **Сравнение с n8n на живом инстансе** (n8n.myaipro.ru работает на этом сервере): одна и та же задача двумя инструментами; когда визуальные пайплайны n8n лучше, когда гибкость Claude-агента важнее. Честный вывод, не «наш инструмент лучше».

### Урок 2. Разбор входящих: почта → классификация → черновики ответов
- Живое подключение Gmail-коннектора (по образцу подключения Drive в М6-01/connect-disks).
- Я создаю в ящике Александра тестовые письма-заявки (вперемешку: заказ, вопрос, жалоба, спам) — или используем реальные с обезличиванием.
- Агент классифицирует, готовит черновики ответов по типам; правило из М6-03 про ПДн в письмах применяется на практике.
- **Блокер:** требуется разовое подключение Gmail-коннектора Александром перед написанием урока.

### Урок 3. QA-контроль: проверка работы менеджеров по чек-листу
- Реалистичный демо-транскрипт звонка/переписки (выдуманный, нейтральный, с типовыми ошибками менеджера).
- Составление чек-листа качества вместе с агентом (это часть практикума — у большинства студентов чек-листа нет).
- Прогон транскрипта по чек-листу: оценка, конкретные цитаты-нарушения, рекомендации.
- Масштабирование через урок 1: та же проверка по расписанию для всех новых звонков.

### Урок 4 (флагман). Тендерный агент: полный конвейер
На реальном тендере с zakupki.gov.ru и нейтральном демо-профиле компании:
1. Поиск подходящих тендеров под профиль компании (реальный поиск по ЕИС).
2. Парсинг документации найденного тендера → извлечение требований.
3. Анализ соответствия: подходит ли компания (лицензии, опыт, финансы), критичные риски.
4. Смета по требованиям + демо-прайс компании (смета — шаг конвейера, не отдельный урок).
5. Итоговый отчёт: участвовать/не участвовать + черновик заявки.

### Рамка модуля: «нейро-сотрудник»
Вывод в конце урока 4 (и коротким анонсом во вводке урока 1): расписания (урок 1) + разбор входящих (урок 2) + QA (урок 3) + конвейер (урок 4) = один «нейро-сотрудник», работающий по правилам без участия владельца. Не отдельный урок — связующая идея.

## Порядок написания

1. Урок 1 (без блокеров: cron и n8n живые на сервере).
2. Урок 3 (без блокеров: демо-данные).
3. Урок 4 (нужен день с доступностью zakupki.gov.ru; демо-профиль сочиняется под найденный тендер).
4. Урок 2 (ждёт Gmail-коннектор от Александра — попросить при ближайшем удобном случае, шаг ~2 минуты).

Порядок публикации на сайте — по номерам уроков (lesson-23…lesson-26), disabled-ссылки для ещё не готовых, как делалось в М6.

## Принципы (унаследованы от М0–М6)

- Всё, что можно сделать вживую — делается вживую; демо только там, где реальных данных нет, с честной пометкой.
- Реальные находки/затыки в процессе подготовки — учебные моменты урока.
- Секреты (вебхуки, токены) — никогда в git/на сайт.
- ПДн — по правилам М6-03.
- Формат уроков: Что получишь / Кому и зачем / Подготовка / Шаги / Чек-лист / Типичные ошибки / ДЗ / Заметки из практики; HTML на сайте по тому же шаблону.
- Обновлять materials-to-bring.md + prep-materials.html при появлении новых требований к материалам (правило из памяти); для М7 требования уже заложены в пп. 6–7.

## Критерий успеха модуля

Александр может назвать свою реальную рутину (входящие, контроль менеджеров, тендеры) и сам сформулировать, какой из четырёх паттернов модуля её закрывает и что для этого нужно подключить.
