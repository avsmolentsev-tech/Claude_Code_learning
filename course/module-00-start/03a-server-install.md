# Ставим Claude Code на сервер

Модуль: M0. Старт · Уровень: Новичок · Время: ~60 мин · Дополнительный урок после урока 03

Страница на сайте: `site/server-install.html`

## Что получишь
Агент, который работает на арендованном сервере круглосуточно — не зависит от твоего компьютера, не требует VPN и не выключается, когда ты закрываешь ноутбук.

## Кому и зачем
Урок 03 поставил агента на твой компьютер — этого достаточно, чтобы пройти весь курс. Сервер нужен, когда упираешься в одну из трёх вещей:

1. **VPN мешает жить.** Сервер стоит в Европе, и для Anthropic это обычный европейский пользователь — агент на сервере работает **без VPN вообще**. VPN останется нужен только браузеру на твоём компьютере, и только в момент авторизации.
2. **Нужна работа 24/7.** Закрыл ноутбук — агент на компьютере остановился. Агент на сервере продолжает. Без этого не будет работать модуль М7: задачи по расписанию, ночные отчёты, мониторинг.
3. **Не хочется грузить рабочий компьютер.** Долгие задачи агента едят память и процессор; на сервере они не мешают твоей основной работе.

**Когда сервер не нужен:** если все файлы лежат на твоём компьютере, задачи разовые и «пока смотрю — работает» тебя устраивает. Тогда сервер только добавит сложности. Возвращайся к этому уроку, когда дойдёшь до М7.

## Что понадобится
- Карта для оплаты сервера — **российская подойдёт** (в отличие от подписки Claude).
- Доступ к почте — туда придут IP и пароль.
- Компьютер с работающим VPN — понадобится один раз, на шаге авторизации.
- Примерно 700–1200 ₽/мес на аренду.

## Шаги

### Шаг 1. Арендуй сервер
Сервис из практики курса — [vdska.ru](https://vdska.ru/?p=58664), принимает российские карты. Подойдёт любой другой хостинг с теми же параметрами.

1. Раздел **VDS/VPS серверы**.
2. **Локация: Латвия или Финляндия.** ⚠️ Ни в коем случае не Россия — Claude не работает с российских IP-адресов, и весь смысл затеи пропадёт.
3. Тариф: **2 ядра, 4 ГБ RAM, 40 ГБ SSD** — рабочий минимум. Голый Claude Code заведётся и на 2 ГБ, но запас нужен: на сервере автора курса (2 ядра, 8 ГБ) в спокойном режиме занято около 2,4 ГБ — агент, два веб-интерфейса из следующего урока и пара ботов. Диск тоже уходит быстрее, чем кажется: рабочие папки с выгрузками, отчётами и дашбордами растут месяцами.
4. Операционная система: **Ubuntu 24.04 LTS**. Не «с панелью управления», не Windows — чистая Ubuntu.
5. Период: месяц. Не понравится — просто не продлишь.

На почту придёт письмо с **IP-адресом** и **паролем root**. Это ключи от сервера — храни как пароль от банка.

### Дальше — две дороги. Выбери свою
Сервер арендован и пустой. Поставить на него агента можно двумя способами, результат одинаковый — разница в том, кто нажимает кнопки.

**Вариант 1 — поручить агенту.** У тебя на компьютере уже стоит Claude Code — а он стоит, если ты прошёл урок 03.
Тогда не делай это руками. Дай задачу своему агенту: он сам подключится к серверу и всё поставит, а ты будешь читать команды и подтверждать. Быстрее, и заодно увидишь, на что агент вообще способен. → **Вариант 1** (сразу ниже)

**Вариант 2 — сделать руками.** Claude Code на компьютере ещё нет — или он не завёлся, или ты как раз из-за этого идёшь на сервер, или просто хочешь понимать каждый шаг.
Тогда идём руками: шаги 2–4, всё с объяснениями. Дольше, но надёжнее — если что-то пойдёт не так, будешь знать, где искать. Шаги 5–8 после этого одинаковые для обоих путей. → **Шаг 2 и дальше**

Выбор не окончательный. Начал коротким путём и застрял на середине — открывай ручную инструкцию с того места, где остановился: шаги там те же самые, просто выполняешь их сам.

### Вариант 1: пусть агент поставит агента
Работа, которая идёт ниже в шагах 2–4, — ровно то, что твой агент умеет: подключиться к серверу и выполнить команды. Поручим ему, а сам будешь смотреть и подтверждать.

Есть техническая деталь, из-за которой «просто дай агенту пароль» не сработает: когда SSH спрашивает пароль, он ждёт, что его наберут руками с клавиатуры. Агент так не умеет. Поэтому сначала один раз ставим ключ — после этого агент ходит на сервер сам.

**А. Поставь ключ на сервер — 2 минуты, один раз.**

Создай ключ (три раза Enter — имя по умолчанию, пароль на ключ можно не ставить):
```
ssh-keygen -t ed25519 -C "мой-сервер"
```

Скопируй его на сервер. **Windows (PowerShell):**
```
$key = Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
ssh root@123.45.67.89 "mkdir -p ~/.ssh; echo '$key' >> ~/.ssh/authorized_keys"
```
**Mac и Linux:**
```
ssh-copy-id root@123.45.67.89
```

Здесь один раз вводишь пароль из письма — руками. Больше он не понадобится. Проверь:
```
ssh root@123.45.67.89 "echo ok"
```
Ответило `ok` без запроса пароля — готово. Заодно сервер стал безопаснее: вход по ключу надёжнее пароля, который перебором подбирает любой бот из интернета.

**Б. Поставь задачу агенту.** Запусти `claude` на своём компьютере и продиктуй обычными словами:

> У меня есть новый сервер Ubuntu 24.04 по адресу root@123.45.67.89, вход по SSH-ключу уже настроен, пароль не нужен. Подключись к нему и подготовь к работе: обнови систему; поставь Node.js 22, git, python3 и tmux; установи Claude Code официальным установщиком с claude.ai; в конце покажи версии node и claude, чтобы я убедился. Выполняй по одной команде, перед каждой пиши простыми словами, что она делает. Ничего лишнего не ставь.

Агент будет спрашивать разрешение на каждую команду — правильно, так и должно быть (урок 04). Читай, что он собирается сделать, и подтверждай. Предложит что-то, чего нет в задаче, — спроси зачем, прежде чем соглашаться.

**Что агент за тебя не сделает:**
- **авторизацию (шаг 5)** — она идёт через твой браузер: агент выведет ссылку, ты откроешь её с включённым VPN и вернёшь код;
- **tmux (шаг 6)** — программу поставит, но привычка запускать работу внутри сессии остаётся твоей.

> **Стоит ли давать агенту root-доступ.** Сервер только что арендован и пуст — терять нечего, а команды ты видишь и подтверждаешь по одной. Правило на будущее: когда на сервере появятся рабочие файлы, выгрузки и доступы к CRM, не выдавай «разрешить всё» одной кнопкой. Тот же принцип, что в уроке 04: права ровно под задачу.

**Зачем этот путь.** Это первый момент в курсе, когда агент настраивает инфраструктуру, а не пишет текст и не считает таблицу. В следующем уроке он пойдёт дальше и развернёт себе веб-интерфейс сам — там ещё проще, потому что агент будет уже на сервере и ключи не понадобятся. Пройдёшь — станет видно, что «поставить и настроить» поручается ему так же спокойно, как «сделать отчёт». Пойдёт не так или захочется понимать каждый шаг руками — ниже полная ручная инструкция.

### Вариант 2: ставим руками — шаги 2–4
> Эти три шага и есть ручной путь. **Если вы пошли вариантом 1, агент уже сделал их за вас** — пролистайте до шага 5, дальше всё общее.

#### Шаг 2. Подключись к серверу
Ничего дополнительно ставить не нужно: SSH встроен и в Windows 10/11, и в macOS.

**Windows:** открой PowerShell (Пуск → набери `PowerShell`).
**Mac:** открой Терминал (Cmd+Пробел → `Терминал`).

Набери, подставив свой IP из письма:

```
ssh root@123.45.67.89
```

- Первый раз спросит `Are you sure you want to continue connecting?` — набери `yes` и Enter. Это нормально: компьютер запоминает сервер.
- Попросит пароль. **Скопируй его из письма и вставь.** При вводе пароля в терминале ничего не отображается — ни точек, ни звёздочек. Это не сломано, так задумано. Вставил → Enter.

Получилось — строка приглашения сменится на `root@your-server:~#`. Ты внутри сервера: всё, что набираешь дальше, выполняется там, а не на твоём компьютере.

#### Шаг 3. Подготовь сервер
Три команды по очереди, каждая — Enter и дождаться окончания.

```
apt update && apt upgrade -y
```
*Обновление системы. Первый раз может идти 2–5 минут. Если спросит про перезапуск сервисов — соглашайся (Enter).*

```
curl -fsSL https://deb.nodesource.com/setup_22.x | bash - && apt install -y nodejs
```
*Node.js 22 — среда, в которой работает агент. Версию 22, а не 20: она понадобится в следующем уроке для веб-интерфейса.*

```
apt install -y git python3 python3-pip python3-venv tmux
```
*Git — для работы с версиями, Python — для расчётов и графиков (пригодится в М4), tmux — понадобится на шаге 6.*

Проверь, что всё встало:

```
node --version
```
Должно показать `v22.x.x`.

#### Шаг 4. Установи Claude Code
Команда — та же, что для Mac в уроке 03: сервер работает на Linux, а установщик у них общий.

```
curl -fsSL https://claude.ai/install.sh | bash
```

После установки перечитай настройки оболочки (или просто отключись и подключись заново):

```
source ~/.bashrc
claude --version
```

Увидел номер версии — готово.

### Дальше — общее для обоих вариантов
Шаги 5–8 делаются одинаково, каким бы путём вы ни пришли. Авторизацию и привычку работать в tmux агент за вас не сделает при всём желании.

### Шаг 5. Авторизуйся
Здесь единственный неочевидный момент урока: **на сервере нет браузера**, а вход в аккаунт идёт через браузер. Решается так:

1. На сервере набери `claude` и выбери вход **по подписке Claude** (не по API-ключу — он оплачивается отдельно и дороже).
2. Агент напечатает длинную ссылку. **Скопируй её и открой в браузере на своём компьютере** — вот тут VPN должен быть включён, потому что claude.ai из России не открывается.
3. Подтверди вход, страница покажет код.
4. **Скопируй код обратно в терминал сервера** и нажми Enter.

Проверка:

```
claude auth status
```

Ответ покажет твою почту и тип подписки. Всё, авторизация сохранена — больше повторять не придётся.

> **Важно про VPN.** VPN был нужен только браузеру на твоём компьютере в момент входа. Сам сервер работает с Anthropic напрямую: он в Европе, для Anthropic это обычный пользователь. Дальше можешь выключить VPN — агент на сервере продолжит работать.

### Шаг 6. Сделай так, чтобы работа не обрывалась
Проблема, о которой узнаёшь неприятным способом: закрыл окно терминала или отвалился интернет — **агент на сервере остановился вместе с сессией**. Полчаса работы в никуда.

Лечится программой `tmux` (ставили на шаге 3). Она держит сессию на сервере живой, даже когда ты отключился.

```
tmux new -s work
```
*Создал рабочую сессию с именем work. Дальше работай как обычно — запускай `claude`.*

Чтобы отключиться, не убивая работу: нажми **Ctrl+B**, отпусти, затем нажми **D**. Вернёшься в обычный терминал, а агент продолжит работать на сервере.

Чтобы вернуться (хоть через час, хоть с другого компьютера):

```
tmux attach -t work
```

Возьми в привычку: подключился к серверу — первым делом `tmux attach -t work`, и ты ровно там, где остановился.

### Шаг 7. Создай рабочую папку и проверь
```
mkdir -p ~/projects/proba
cd ~/projects/proba
claude
```

Поставь первую задачу: «Создай файл проверка.md и напиши в нём три строки о том, что ты умеешь». Файл появился — сервер работает.

### Шаг 8. Дальше — подключаемся по-человечески
Чёрное окно терминала работает, но проводить в нём рабочий день не хочется: не видно файлов, не видно правок агента.

**Подключение из VS Code разобрано в уроке [М0-06](06-vscode.md)** — он идёт дальше по программе, через пару уроков. Забегать вперёд не надо: дойдёшь по порядку и в конце того урока найдёшь раздел «Если твой агент живёт на облачном сервере» — расширение Remote-SSH, подключение к серверу, открытие его папок. Возвращаться сюда не придётся.

А пока хочешь добраться до агента с телефона или из браузера — это следующий урок, он как раз про это.

Итог, к которому придёшь: то же окно VS Code, тот же рабочий цикл с диффами, но файлы лежат на сервере, и закрытый ноутбук больше не останавливает агента.

## Типичные ошибки
| Симптом | Причина | Решение |
|---|---|---|
| `Connection refused` / `timeout` | Неверный IP, сервер ещё грузится или выключен | Скопируй IP из панели (не набирай руками), проверь статус «Running», подожди 2 минуты |
| `Permission denied (password)` | Опечатка в пароле | Копируй-вставляй пароль из письма; помни — при вводе символы не отображаются |
| Пароль не вставляется в PowerShell | Ctrl+V там работает не всегда | Правый клик мышью вставляет из буфера |
| Агент не может зайти на сервер, всё упирается в запрос пароля | SSH-ключ не установлен — агент не может ввести пароль руками | Пройди пункт А короткого пути: `ssh-keygen`, затем копирование ключа |
| `node: command not found` | Node.js не установился | Повтори команду из шага 3 целиком, вместе с `curl` |
| `claude: command not found` после установки | Оболочка не перечитала настройки | `source ~/.bashrc` либо отключись и подключись заново |
| Ссылка авторизации не открывается | VPN на твоём компьютере выключен | Включи VPN — ссылка ведёт на claude.ai |
| Закрыл терминал — агент перестал работать | Сессия не в tmux | Всегда запускай работу внутри `tmux new -s work` |
| Агент тормозит, сервер «висит» | Не хватает памяти на тарифе 2 ГБ | Перейди на 4 ГБ либо не запускай тяжёлые задачи параллельно |

## Безопасность
- **Смени пароль root сразу:** команда `passwd`, ввести новый дважды. Пароль из письма ходил по почте открытым текстом.
- **Файл `~/.claude` на сервере содержит токен доступа к твоей подписке** — относись как к паролю. Отдаёшь сервер или удаляешь — сначала `claude auth logout`.
- **Сервер доступен из интернета всему миру.** Не держи на нём персональные данные клиентов и оригиналы договоров — правила из М6-03 действуют здесь в полной мере, работай с обезличенными копиями.
- **Обновляй систему** раз в месяц: `apt update && apt upgrade -y`.

Подними сервер, авторизуй агента и **выключи VPN**. Поставь агенту любую задачу из урока 04 и убедись, что она выполняется. Это и есть главный практический выигрыш урока: рабочий агент, которому не нужен VPN.

## Заметки из практики
- Пароль в терминале не отображается при вводе — на этом спотыкаются почти все, кто впервые видит SSH. Люди решают, что клавиатура не работает, и набирают пароль по три раза.
- Соблазн взять сервер в России ради скорости и цены заканчивается одинаково: агент не авторизуется, потому что Anthropic не пускает российские IP. Локация — единственный параметр, на котором нельзя экономить.
- Про tmux вспоминают только после того, как потеряют первую длинную сессию. Лучше приучиться сразу.
