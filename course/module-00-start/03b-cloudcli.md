# CloudCLI: агент в браузере и на телефоне

Модуль: M0. Старт · Уровень: Новичок+ · Время: ~60 мин · Дополнительный урок после урока «Ставим Claude Code на сервер»

Страница на сайте: `site/cloudcli-install.html`

## Что получишь
Свой личный кабинет для агента: заходишь по адресу вроде `claude.твойдомен.ру`, вводишь пароль — и работаешь с Claude Code в браузере. С компьютера, с планшета, с телефона из машины.

## Кому и зачем
Предыдущий урок дал агента на сервере — но добираться до него можно только через терминал по SSH. С компьютера это терпимо, с телефона — мучение.

**CloudCLI** — веб-интерфейс поверх Claude Code. Тот же агент, те же файлы, та же подписка, но в окне браузера: чат, дерево файлов, история сессий, git.

Зачем это предпринимателю:
- **Поставить задачу с телефона.** Едешь в машине, вспомнил — открыл, надиктовал, агент делает.
- **Вернуться к разговору с другого устройства.** Начал на компьютере, продолжил с планшета — история сессий общая.
- **Дать доступ сотруднику,** не объясняя, что такое терминал (каждому — свой экземпляр, см. в конце урока).

> ⚠️ **Честно о том, что это такое.** CloudCLI — не продукт Anthropic, а сторонний проект с открытым исходным кодом ([siteboon/claudecodeui](https://github.com/siteboon/claudecodeui), сайт [cloudcli.ai](https://cloudcli.ai)). Своего ИИ у него нет — он работает на твоей подписке Claude. Плюс открытого кода: бесплатно и всё видно. Минус: обновления и безопасность — твоя ответственность, а не Anthropic.

## Что понадобится
- Сервер из предыдущего урока с авторизованным Claude Code.
- **Node.js версии 22 или выше** — проверь командой `node --version`. Если стоит 20 — переустанови по шагу 3 предыдущего урока, CloudCLI на 20-й не запустится.
- **Домен или поддомен — обязательно.** Без него не получить сертификат, а выставлять интерфейс в интернет без шифрования нельзя. Подойдёт поддомен уже существующего сайта — покупать отдельный не нужно (шаг 0).
- Полчаса ожидания: A-запись расходится по интернету не мгновенно, поэтому шаг 0 делаем первым.

## Шаги

### Шаг 0. Купи домен и направь его на сервер
Это делается **до всего остального** и только руками: панель регистратора агенту недоступна, а сертификат HTTPS в конце урока не выдастся, пока домен не указывает на сервер. Запись расходится по интернету не мгновенно — поэтому запускаем её первой, а пока ждём, занимаемся установкой.

**Если домен уже есть** — подойдёт поддомен рабочего сайта, отдельный покупать не нужно.

**Если домена нет.** Регистратор подойдёт любой; в курсе используем [reg.ru](https://www.reg.ru/domain/new/?rlink=reflink-31998683) — российские карты, интерфейс и поддержка на русском. При оплате промокод `A356-851F-78F0-570A` даёт **скидку 5%**.

> ⚠️ **Домен там брать можно, сервер — нет.** Все дата-центры reg.ru в Москве, а серверу нужна зарубежная локация: с российского IP агент не авторизуется в Claude. Сервер берём по предыдущему уроку (Латвия/Финляндия), домен — у кого угодно, он на это не влияет.

Дальше нужно создать **A-запись** — строчку в настройках домена, которая говорит интернету: «адрес `claude.твойдомен.ру` ведёт вот на этот IP». Без неё домен есть, а никуда не ведёт.

**A-запись в reg.ru — по шагам**

*Сначала проверь, где вообще управляется твой домен.* Это первое, обо что спотыкаются: человек добавляет запись в личном кабинете, а домен ею не управляется, и ничего не происходит. Открой раздел **Домены** в личном кабинете, кликни по домену и посмотри блок **«DNS-серверы и управление зоной»**:
- `ns1.reg.ru` и `ns2.reg.ru` — всё правильно, иди по шагам ниже;
- `ns1.hosting.reg.ru` и `ns2.hosting.reg.ru` — домен управляется хостингом reg.ru, запись добавляется в панели хостинга;
- что-то другое (Cloudflare, Yandex, другой регистратор) — записи живут там.

Шаги для случая `ns1.reg.ru` / `ns2.reg.ru`:
1. Личный кабинет → раздел **Домены** → кликни по строке с нужным доменом.
2. Блок **«DNS-серверы и управление зоной»** → **Изменить**.
3. **Добавить запись**.
4. В шторке справа выбери тип **A**.
5. Заполни два поля:
   - **Subdomain** — `claude`. Только имя поддомена, без домена и без точки. Не `claude.твойдомен.ру`, иначе получится `claude.твойдомен.ру.твойдомен.ру`.
   - **IP Address** — IP сервера из письма хостинга, вида `123.45.67.89`.
6. **Готово**.

Значок `@` в поле Subdomain означает сам домен без поддомена, `*` — все поддомены сразу. Нам нужен именно `claude`: основной домен пусть остаётся под сайтом, если он там есть.

**Проверь, что запись разошлась.** Обычно 10–30 минут, изредка дольше. Из терминала на своём компьютере (работает и в Windows PowerShell, и на Mac):

```
nslookup claude.твойдомен.ру 8.8.8.8
```

В ответе должен быть IP твоего сервера. Адрес `8.8.8.8` не случаен: он заставляет спросить публичный DNS Google напрямую, в обход кэша провайдера и компьютера — иначе можно полчаса смотреть на старый ответ и думать, что запись не работает.

> **Не запускай задачу агенту, пока проверка не прошла.** Certbot из шага 5 выдаёт сертификат, только если домен уже указывает на сервер: он сам стучится по этому адресу. Поспешишь — получишь ошибку на последнем шаге и будешь разбираться на ровном месте.

У других регистраторов принцип тот же: найти управление DNS-зоной, добавить запись типа A, в имя вписать `claude`, в значение — IP сервера. Отличаются только названия кнопок.

### Короткий путь: пусть агент развернёт себе интерфейс сам
В прошлом уроке агент на компьютере ставил агента на сервер, и ради этого пришлось возиться с SSH-ключом. Здесь проще: агент **уже живёт на сервере**, все команды локальные, ключи и пароли не нужны. Он развернёт интерфейс, через который ты потом будешь им же и управлять.

**Проверь, что шаг 0 уже сделан.** Задачу агенту ставим **после** того, как `nslookup claude.твойдомен.ру 8.8.8.8` вернул IP твоего сервера. Пока запись не разошлась, последний пункт задачи — сертификат — гарантированно упадёт.

**Задача агенту.** Подключись к серверу по SSH, запусти `claude` и вставь (подставь свой домен):

> Ты работаешь на этом сервере под Ubuntu. Разверни здесь CloudCLI — веб-интерфейс для Claude Code, пакет `@cloudcli-ai/cloudcli`.
>
> 1. Проверь, что Node.js версии 22 или выше. Если ниже — остановись и скажи мне, дальше не иди.
> 2. Установи пакет глобально через npm.
> 3. Создай папку `/root/cloudcli` и в ней файл `.env` со строками: `SERVER_PORT=3005`, `HOST=127.0.0.1`, `WORKSPACES_ROOT=/root/projects`. Значение `JWT_SECRET` сгенерируй командой `openssl rand -hex 32` и запиши сразу в файл — **в чат его не выводи**.
> 4. Сделай службу systemd с именем `cloudcli`, чтобы сервис сам поднимался после перезагрузки и после сбоя. Запусти её и покажи статус.
> 5. Поставь nginx и настрой обратный прокси на `127.0.0.1:3005` для домена `claude.мойдомен.ру`. Обязательно с заголовками `Upgrade` и `Connection "upgrade"` и с `proxy_read_timeout 3600` — без них ответы агента не будут появляться в чате, а долгие задачи будут обрываться.
> 6. Получи HTTPS-сертификат через certbot для этого домена, с перенаправлением http на https. Почту для certbot спроси у меня.
> 7. В конце проверь и покажи мне: служба `active (running)`, `nginx -t` без ошибок, сайт открывается по https.
>
> Перед каждой командой пиши простыми словами, что она делает. A-запись домена я уже настроил.

> **Почему «в чат его не выводи».** `JWT_SECRET` — ключ от твоего интерфейса. История переписки с агентом легко оказывается на скриншоте, в пересланном сообщении или в отчёте. Привычка «секреты пишем сразу в файл, а не показываем» пригодится дальше во всём курсе — с токенами CRM, вебхуками и ключами API.

**Что останется тебе:**
- **включить инструменты** в настройках интерфейса (шаг 6) — делается мышкой в браузере, агент туда не дотянется;
- **проверить с телефона** (шаг 7) — собственно то, ради чего всё затевалось.

Пойдёт не так или захочется понимать каждую строчку — ниже полная ручная инструкция. Она же пригодится, чтобы прочитать и проверить сделанное агентом: доверять стоит, но посмотреть на `.env` и конфиг nginx своими глазами полезно.

### Шаг 1. Установи CloudCLI
Подключись к серверу по SSH и выполни:

```
npm install -g @cloudcli-ai/cloudcli
```

Проверка:

```
cloudcli --version
```

### Шаг 2. Первый запуск — убедиться, что работает
```
cloudcli
```

По умолчанию поднимется на порту 3001. Открой в браузере `http://ТВОЙ_IP:3001` — увидишь интерфейс, а слева — свои папки с сервера.

Останови его (**Ctrl+C**) и читай дальше: **так оставлять нельзя**. Сейчас это открытая дверь — адрес доступен всему интернету, пароль передаётся незашифрованным, и любой, кто наткнётся на порт, получит доступ к агенту с твоей подпиской. Следующие три шага закрывают эту дыру.

### Шаг 3. Настрой конфигурацию
Создай рабочую папку и файл настроек:

```
mkdir -p /root/cloudcli
nano /root/cloudcli/.env
```

Вставь (редактор `nano`: вставка — правый клик, сохранить — Ctrl+O затем Enter, выйти — Ctrl+X):

```
SERVER_PORT=3005
HOST=127.0.0.1
WORKSPACES_ROOT=/root/projects
JWT_SECRET=сюда_вставить_длинную_случайную_строку
```

Что означает каждая строка:
- **SERVER_PORT** — порт, на котором работает сервис.
- **HOST=127.0.0.1** — самое важное. Означает «слушать только изнутри сервера»: снаружи напрямую попасть нельзя, только через nginx из шага 5. Это и есть закрытая дверь.
- **WORKSPACES_ROOT** — папка, файлы которой ты увидишь в интерфейсе.
- **JWT_SECRET** — ключ, которым подписываются твои входы. Сгенерируй свой:

```
openssl rand -hex 32
```

Скопируй выданную строку в `.env`. **Это пароль** — не показывай никому, не выкладывай в репозиторий.

### Шаг 4. Автозапуск: чтобы поднимался сам
Сейчас сервис умрёт, как только ты закроешь терминал или перезагрузишь сервер. Поручим это системе.

```
nano /etc/systemd/system/cloudcli.service
```

Содержимое:

```
[Unit]
Description=CloudCLI web UI for Claude Code
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/cloudcli
EnvironmentFile=/root/cloudcli/.env
ExecStart=/usr/bin/cloudcli
Restart=on-failure
RestartSec=3
Environment=HOME=/root

[Install]
WantedBy=multi-user.target
```

Запусти и включи автозагрузку:

```
systemctl daemon-reload
systemctl enable --now cloudcli
systemctl status cloudcli
```

Должно быть `active (running)`. Теперь сервис переживает и обрыв связи, и перезагрузку сервера, а `Restart=on-failure` поднимет его после сбоя.

### Шаг 5. Открой доступ снаружи по HTTPS
Домен уже направлен на сервер (шаг 0). Осталось пустить запросы внутрь — но безопасно, через шифрованное соединение.

**5.1. Поставь nginx** — он примет запрос из интернета и передаст его CloudCLI внутрь:

```
apt install -y nginx
nano /etc/nginx/sites-available/cloudcli
```

Содержимое (подставь свой домен):

```
server {
    listen 80;
    server_name claude.твойдомен.ру;

    location / {
        proxy_pass http://127.0.0.1:3005/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600;
        client_max_body_size 100m;
    }
}
```

Две строки здесь критичны, без них интерфейс загрузится, но ответы агента не будут появляться в чате: `Upgrade` и `Connection "upgrade"` — они пропускают постоянное соединение, по которому агент печатает ответ по мере готовности. Третья важная — `proxy_read_timeout 3600`: без неё nginx оборвёт долгую задачу через минуту.

Включи конфигурацию:

```
ln -s /etc/nginx/sites-available/cloudcli /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

**5.2. Включи HTTPS** — бесплатный сертификат ставится одной командой:

```
apt install -y certbot python3-certbot-nginx
certbot --nginx -d claude.твойдомен.ру
```

Certbot спросит почту, согласие с условиями и предложит перенаправлять http на https — соглашайся. Сертификат обновляется сам.

Открой `https://claude.твойдомен.ру` — замок в адресной строке, интерфейс работает. Теперь то же самое открывается и с телефона.

### Шаг 6. Настрой права агента
**Все инструменты в CloudCLI по умолчанию выключены** — это сознательное решение авторов: свежеустановленный интерфейс не может ничего натворить.

Нажми **шестерёнку** в боковой панели и включай только то, что нужно: чтение и запись файлов — сразу, выполнение команд — осознанно. Логика та же, что в уроке М0-04: агент должен иметь ровно те права, которые нужны для задачи.

### Шаг 7. Проверь с телефона
Открой адрес на телефоне, войди, выбери папку и поставь задачу голосовым вводом. Это и есть тот самый сценарий, ради которого ставился урок.

## Несколько пользователей
Если нужен доступ сотруднику — не давай свой вход, а подними ему отдельный экземпляр:
1. Своя папка (`/root/cloudcli-ivan`) со своим `.env`: другой `SERVER_PORT` (например, 3006) и **свой** `JWT_SECRET`.
2. Свой файл сервиса (`cloudcli-ivan.service`) — копия из шага 4 с изменёнными путями.
3. Свой поддомен и свой блок nginx с проксированием на новый порт.

Так у каждого своя история сессий и свои файлы. Помни: **каждый экземпляр тратит лимиты твоей подписки** — это общий счёт, а не отдельные.

## Чек-лист
- [ ] `node --version` показывает v22 или выше
- [ ] `systemctl status cloudcli` — active (running)
- [ ] В `.env` стоит `HOST=127.0.0.1`, а `JWT_SECRET` сгенерирован мной, а не взят из примера
- [ ] `nslookup claude.домен.ру 8.8.8.8` возвращает IP моего сервера
- [ ] Домен открывается по https, замок в адресной строке
- [ ] Порт 3005 напрямую снаружи недоступен

- [ ] Если разворачивал агентом: сам открыл `.env` и конфиг nginx и убедился, что там то, что заказывал
- [ ] Проверил вход с телефона
- [ ] Сервис пережил перезагрузку сервера (`reboot`, затем зайти снова)

## Типичные ошибки
| Симптом | Причина | Решение |
|---|---|---|
| При установке ошибки про версию Node | Node.js ниже 22 | Переустанови Node 22 (шаг 3 предыдущего урока), затем ставь CloudCLI заново |
| Интерфейс открылся, но ответы агента не приходят | В nginx нет заголовков Upgrade/Connection | Проверь конфиг из шага 5.2 целиком |
| Долгая задача обрывается примерно через минуту | Не задан `proxy_read_timeout` | Добавь `proxy_read_timeout 3600;` и перезагрузи nginx |
| `systemctl status` показывает failed | Опечатка в `.env` или занят порт | `journalctl -u cloudcli -n 50` покажет причину |
| Сайт не открывается по домену | A-запись ещё не разошлась | `nslookup claude.домен.ру 8.8.8.8` — если IP не твой, жди; до часа это норма |
| Открывается `claude.домен.ру.домен.ру` или запись «не работает» | В поле Subdomain вписали полный адрес вместо одного слова | В Subdomain только `claude`, без домена и точки |
| Добавил запись в кабинете — ничего не изменилось | Домен управляется другими DNS-серверами | Проверь блок «DNS-серверы и управление зоной» |
| Certbot не выдаёт сертификат | Домен ещё не указывает на сервер либо закрыт порт 80 | Дождись DNS, проверь `nginx -t` |
| Агент не отвечает, хотя интерфейс работает | Claude Code на сервере не авторизован | На сервере: `claude auth status`, при необходимости войти заново |
| Все кнопки инструментов серые | Инструменты выключены по умолчанию | Шестерёнка → включить нужные (шаг 6) |

## Безопасность
- **`HOST=127.0.0.1` — не «одна из настроек», а замок на двери.** Поставишь `0.0.0.0` — сервис станет доступен всему интернету напрямую, в обход HTTPS.
- **`JWT_SECRET` уникален для твоей установки.** Скопируешь чужой из инструкции — постороннему станет проще подделать вход.
- **Это доступ к твоей подписке и твоим файлам.** Утёк пароль — утекли и лимиты, и содержимое рабочих папок.
- **Обновляй:** `npm update -g @cloudcli-ai/cloudcli && systemctl restart cloudcli` — раз в месяц.
- **Персональные данные клиентов** на сервере, открытом в интернет, — плохая идея. Правила из М6-03 действуют.

## Заметки из практики
- **Выбор модели живёт в интерфейсе, а не в конфигах.** CloudCLI запускает агента с явным указанием модели из своего селектора, и этот выбор сильнее любых настроек в файлах. Правишь конфиг, ожидая другую модель, — не сработает: смотри селектор.
- **Карточка «default» — не то, что кажется.** Она указывает не на твои настройки, а на текущую модель по умолчанию, и эта цель двигается: в разное время подпись показывала разные модели. Нужна конкретная — выбирай её явно.
- **Модель выбирается в момент старта чата.** Переключил селектор на середине разговора — текущий диалог не изменится, только следующий новый.
- **«Effort» — это не модель.** Кнопка внизу поля ввода (Default / Low / Medium / High / Max) управляет глубиной рассуждений. Максимум жжёт лимиты заметно быстрее и почти ничего не даёт на обычных задачах вроде текстов и отчётов — держи Default, повышай только на сложной логике. Эту кнопку легко принять за выбор модели: автор курса перепутал дважды.
