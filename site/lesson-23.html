Агент по расписанию: работает, пока ты спишь

Команды проверены вживую при подготовке урока 24.07.2026 (Claude Code 2.1.205). Сравнение с n8n — на реально работающем инстансе, не по скриншотам из интернета.

Что получишь

Понимание трёх механизмов, которые превращают агента из «собеседника в чате» в автоматику: headless-режим (агент без диалога), расписание (cron), субагенты (параллельная работа). Плюс честное сравнение с n8n на живом инстансе — когда нужен визуальный конструктор, а когда агент.

Кому и зачем

Всё, что делалось в курсе до сих пор, требовало тебя: открыть диалог, написать задачу, посмотреть результат. Но половина ценности автоматизации — в задачах, которые должны выполняться без тебя: ночная сводка по вчерашним продажам, утренняя проверка новых заявок, еженедельный отчёт. Этот урок — мост от «агента-собеседника» к «агенту-сотруднику», и он же техническая основа для всех следующих уроков модуля.

Подготовка

Установленный Claude Code из М0-03. Всё остальное — по ходу урока.

Шаги

Шаг 1. Headless-режим: агент без диалога (15 мин)

До сих пор агент работал в диалоге: ты пишешь — он отвечает. Но ту же команду можно запустить «в одну строку», без открытия чата — флаг -p (print):

claude -p "Прочитай файлы в папке отчёты и напиши сводку в файл сводка.md"

Агент выполнит задачу и завершится — никакого диалога, только результат. Проверено вживую при подготовке урока:

$ claude -p "Ответь одним словом: работает"
Работает.

Зачем это нужно: команду в одну строку можно вставить куда угодно — в скрипт, в планировщик, в другую программу. Это и есть дверь к автоматизации: всё, что агент умеет в диалоге, он умеет и без тебя.

Полезные дополнения к -p:

  • --model — выбрать модель под задачу (дешёвую для рутины, мощную для сложного);
  • --allowedTools — заранее разрешить конкретные инструменты, чтобы агент не ждал подтверждений, которых некому дать ночью.

Важно про разрешения. В headless-режиме некому нажать «разрешить». Поэтому автоматическому агенту заранее выдают только те права, которые нужны для конкретной задачи — тот же принцип наименьших привилегий, что с вебхуком Bitrix24 в М6-02. Не «разрешить всё», а «разрешить читать эту папку и писать в этот файл».

Шаг 2. Расписание: cron (15 мин)

Cron — штатный планировщик Linux/Mac (на Windows та же роль у «Планировщика заданий»). Строка расписания выглядит так:

0 7 * * *  claude -p "Собери сводку по вчерашним заявкам из папки Заявки в файл сводка-сегодня.md"

Пять полей перед командой — минута, час, день месяца, месяц, день недели. 0 7 * * * — «каждый день в 7:00». Другие типовые расписания:

0 7 * * 1     — каждый понедельник в 7:00 (еженедельный отчёт)
*/30 9-18 * * — каждые 30 минут с 9 до 18 (проверка новых заявок в рабочее время)
0 22 * * 5    — в пятницу в 22:00 (недельная сводка к утру понедельника)

Добавить строку в расписание: команда crontab -e (откроется редактор), вставить строку, сохранить. Посмотреть текущее расписание: crontab -l.

Учебный момент из практики. Автоматическому запуску нужны абсолютные пути (cron не знает, «в какой папке ты работал») и перенаправление вывода в лог-файл, иначе о ночных ошибках никто не узнает:

0 7 * * * cd /home/user/ИИ-проекты && claude -p "..." >> /home/user/логи/агент.log 2>&1

Правило: у ночного агента должен быть лог, и утро начинается с взгляда в него — хотя бы первое время, пока не появится доверие к конкретной задаче.

Шаг 3. Субагенты: параллельная работа (10 мин)

Внутри одной задачи агент умеет запускать помощников — субагентов, каждый со своим отдельным контекстом. Попроси в обычном диалоге:

Проверь три папки — Заявки, Договоры, Отчёты — параллельно тремя субагентами: в каждой найди файлы за вчера и составь общий список.

Агент разобьёт работу на три параллельных потока и соберёт результаты. Когда это выгодно:

  • Независимые куски — три папки, пять сайтов конкурентов, десять документов: не по очереди, а одновременно.
  • Большие объёмы — каждый субагент читает свою часть в собственный контекст, итог не «раздувается».

Когда не выгодно: задачи, где следующий шаг зависит от предыдущего (сначала прочитать сделку — потом заполнить шаблон), — там параллелить нечего.

Шаг 4. n8n или Claude-агент: живое сравнение (15 мин)

n8n — популярный визуальный конструктор автоматизаций: рисуешь схему из блоков (триггер → действие → действие), она выполняется по событию или расписанию. Сравнение в этом уроке — не по скриншотам из интернета: на сервере автора курса реально работает собственный n8n-инстанс (проверено при подготовке: {"status":"ok"} на health-запрос), и часть личных автоматизаций там.

Одна и та же задача — «раз в день собрать заявки и подготовить черновики ответов» — двумя инструментами:

n8nClaude-агент (headless + cron)
Как выглядитВизуальная схема из блоковОдна строка в расписании
Сильная сторонаНадёжные повторяемые конвейеры: вебхуки, API-интеграции (сотни готовых блоков), одно и то же каждый разЗадачи с пониманием текста: классифицировать письмо, написать черновик, оценить документ — то, что в блоки не укладывается
Слабая сторонаКак только нужен «интеллект» внутри шага — всё равно вызывает LLM-блок, и схема усложняетсяДороже на простых механических шагах: пересылка файла из точки А в точку Б агенту не нужна
Кто настраиваетПроще делегировать: схему видно глазамиНужно уметь сформулировать задачу текстом (это и есть навык курса)

Честный вывод. Это не конкуренты, а слои: n8n хорош как «трубопровод» (события, доставка данных из сервиса в сервис), агент — как «голова» (понять, решить, написать). Реальные зрелые автоматизации часто выглядят как «n8n доставляет данные → агент думает → n8n разносит результат». Если у тебя нет ни того ни другого — начинай с агента: он покрывает больше сценариев одним инструментом, а n8n добавишь, когда упрёшься в интеграции.

Рамка модуля: к чему всё идёт

Этот урок — первый кирпич «нейро-сотрудника»: расписание (этот урок) + разбор входящих (урок 2) + контроль качества (урок 3) + рабочий конвейер (урок 4, тендерный агент) = сотрудник, который каждый день делает рутину по правилам, а тебе приносит только результаты и исключения. Держи эту картинку в голове по мере прохождения модуля.

Домашнее задание

Выбери одну свою реальную повторяющуюся задачу (сводка, проверка, отчёт). Сначала прогони её вручную через claude -p днём, посмотри результат. Если устраивает — поставь в cron на завтрашнее утро с логом в файл. Утром сравни: что агент сделал сам и что бы ты сделал иначе.

Заметки из практики

Сравнение с n8n в этом уроке появилось не из теории: у автора курса на сервере параллельно живут и n8n-автоматизации, и Claude-агенты, и граница между ними нащупана на собственных шишках. Самое частое заблуждение новичка — «выбрать один инструмент навсегда»; на практике трубопровод и голова — разные роли, и спор «n8n vs агенты» обычно означает, что человек ещё не увидел, как они складываются.
